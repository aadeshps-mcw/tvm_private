weights out for keeping json lightweight
Intel’s DNNL engine needs to read weights directly from contiguous binary blocks of RAM so your CPU can execute AVX-512 or AMX vector instructions on them.

By keeping params separate, TVM preserves the weights as raw binary arrays.

If you host your model in a production server and run multiple inference instances simultaneously, you only need one copy of the static weights loaded into RAM.
By keeping the execution graph (graph_json) and the model weights (params) decoupled, multiple runtime engine threads can share the exact same weight buffer in memory without duplication, saving massive amounts of system memory.


Once compilation finishes, the Relay IR structures are completely destroyed. TVM needs a way to save the structural blueprint of your network inside the final compiled library file (like a .so or .tar file) so it can be reloaded later or deployed on a production server. A platform-agnostic text format like JSON is ideal for this storage.


Intel's oneDNN (DNNL) library cannot execute a raw JSON text string directly. It is a C++ math library that requires native C++ objects to perform matrix multiplications.

Serialization is done to freeze and save the model structure into a lightweight, portable text format when the compiler finishes its job.

Deserialization is done to thaw and rebuild that structure into live C++ objects and raw memory pointers so that the CPU hardware can actually execute the math operations during an inference forward pass.
